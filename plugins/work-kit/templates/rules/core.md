# {{project}} 작업 룰 (항상 적용)

> `.claude/rules/` 는 Claude Code 가 매 세션 자동으로 읽는다. 협의 없이 어길 수 없다.
> `paths:` 가 붙은 파일은 해당 경로를 만질 때만 추가로 실린다 — 상세 형식은 거기에 있다.

## 1. 업무 흐름 — `process.md`

일은 **PRD → Tech Spec(선택) → Card(Task list) → Commit → 주간보고** 로 흐른다.
전체 그림과 문서별 자리는 늘 로드되는 `process.md`, 형식은 그 폴더를 만질 때 로드되는
`prd.md`·`tech-spec.md`·`card.md`·`weekly-report.md`.

**문서를 만드는 것과 작업에 착수하는 것은 다르다.** Card 는 할 일을 등록한 것이고,
구현은 **사용자가 그 카드 착수를 지시했을 때만** 시작한다. 할 일을 발견한 시점에는 Card(작업)나
이슈(버그)로 등록만 한다(§4). **결정이 남아 있으면**(Tech Spec 의 `### 팀 결정 대기` 등) **판단부터 받는다.**

## 2. 일일 리포트 — `docs/reports/daily/`

**`/daily-report` 명령으로 작성한다.** 형식·규칙은 그 명령 문서에 있다.
주간 보고는 **`/weekly-report`** — PRD 기준 진행 현황을 Card 의 체크 상태로 판정해 `docs/reports/weekly/` 에 만든다.
일일 리포트는 대응 방안과 "그 주에 손댄 카드" 를 가리는 재료로 쓴다. 형식은 그 폴더를 만질 때 로드되는 `weekly-report.md`.

## 3. 커밋 — 작업 단위로 쪼개고, 승인은 MR 에서 받는다

- **커밋은 논리 단위 하나에 하나다.** Card 할 일 하나, 리뷰 지적 한 묶음, 마이그레이션 하나,
  fixture 갱신 하나. 코드와 그 테스트는 같은 커밋에 넣는다. 커밋 메시지 본문에 **왜** 를 쓴다.
  "여러 할 일을 한 커밋에 몰기"·"끝에 한 번에 커밋" 은 하지 않는다 — 리뷰·되돌리기·bisect 가 안 된다.
- **커밋마다 승인받지 않는다.** 작업 단위가 끝나고 게이트가 green 이면 그냥 커밋한다.
  사용자 승인은 **MR** 에서 받는다(MR 을 열거나 push 로 갱신한 뒤 알린다).
- **MR 은 코드 리뷰를 마친 뒤에만 연다.** 리뷰는 push(MR 갱신) 전에 그동안 쌓인 커밋을 모아 한 번 돌려도 된다.
- Card 의 할 일은 그 할 일을 커밋하고 테스트를 통과했을 때 `[x]` 로 바꾼다(`card.md` §5. Card 는 미추적이라 커밋엔 안 들어간다).

커밋 직전 확인:

- **전체 테스트 스위트**(`{{test}}`)를 돌린다. 실패하면 커밋하지 않는다 — 출력을 그대로 보고한다
- 현재 브랜치를 확인한다. 보호 브랜치({{protectedBranches}})에 쌓지 않는다. 이미 MR 이 열린 브랜치는
  **그 MR 범위의 작업만** 쌓고, 관련 없는 작업이면 새 브랜치를 판다
- git 추적 파일에 사내 정보가 들어가지 않았는지 본다(§5)

**사용자가 "MR merge 했어" 라고 하면 그 턴에 로컬 브랜치도 지운다.**
묻지 않고 한다 — 지운 브랜치 이름을 답변에 적는다.

- `git fetch --prune origin` 뒤 `git branch --merged origin/{{integrationBranch}}` 로 **병합을 확인하고** `git branch -d` 로 지운다.
  그 브랜치에 서 있으면 먼저 `{{integrationBranch}}` 로 옮겨 `git pull` 한다
- 그 MR 의 브랜치만이 아니라 **그 시점에 `origin/{{integrationBranch}}` 에 병합된 로컬 브랜치를 전부** 지운다. 보호 브랜치({{protectedBranches}})는 남긴다
- 이력상 병합이 아니어도(squash·cherry-pick) `git cherry origin/{{integrationBranch}} {브랜치}` 가 전부 `-` 이고 원격 브랜치가 사라졌으면(`gone`) `-D` 로 지운다
- **워크트리에 물린 브랜치는 지우지 않고 알린다** — 워크트리를 닫는 것은 §6 순서를 따르고, 닫을지는 묻는다
- 병합되지 않은 브랜치는 건드리지 않는다

**MR 은 `.gitlab/merge_request_templates/Default.md` 를 채워 쓴다.**
퀵 액션(`/assign me`)은 지우지 않고, 미추적 문서(`docs/card/`·`docs/prd/` 등)는 링크하지 않는다 — 나머지는 `gitlab-templates.md`.

## 4. 발견한 문제·할 일 — 발견한 그 턴에 등록한다

**지금 고치지는 않지만 남겨둘 가치가 있는 것**을 발견했을 때. 구현 중만이 아니다 —
**질문에 답하다가, 로그를 보다가, 원인을 찾다가 발견한 것도 같다.**

**발견한 그 턴이 끝나기 전에 아래 표대로 원고 파일을 쓴다.**
"이건 이슈 대상입니다"·"등록할까요?" 라고 **말만 하고 넘어가지 않는다** — 등록은 묻지 않고 한다
(묻는 것은 착수다). 답변 끝에 **무엇을 어느 파일에 등록했는지** 경로와 함께 적는다.
사용자는 내가 어떤 규칙을 따랐는지 볼 수 없으므로, 그 한 줄이 규칙을 지켰다는 유일한 표시다.

| 발견했다 | 그 턴에 하는 일 |
|---|---|
| 장애·버그·오동작 | `docs/issues/{순번}_{주제}.md` 원고를 쓴다 |
| 남은 작업("이건 나중에", "따로 해야 한다") | `docs/card/` 에 Card 를 쓴다 |
| 내가 정할 수 없는 결정 | `docs/detected_issues.md` 에 한 줄 |
| 그 자리에서 고쳤다 | 등록하지 않는다. 커밋 메시지에 **왜** 를 남긴다 |

어디로 보낼지의 판단 기준은 하나다.

| 상황 | 어디로 |
|---|---|
| **장애·버그**이고 내가 판단해서 착수할 수 있다 | **{{issueTool}} 이슈** — `.gitlab/issue_templates/` 의 `Bug.md`·`Incident.md`. 이슈에서 처리하고 Card 는 만들지 않는다. 원고는 **전부 `docs/issues/`** 에 둔다. type·형식은 `issues.md` |
| **해야 할 작업**(기능 추가·개선·리팩터링·정리)이고 내가 판단해서 착수할 수 있다 | **Card** — 이슈를 만들지 않는다. PRD 기능에 속하면 그 PRD 폴더에, 아니면 `docs/card/PRDx/` 에(`card.md`) |
| **결정이 나에게 없다**(상사 판단·조직 방침·도입 계획) | **`docs/detected_issues.md`** |
| 지금 바로 고칠 수 있고 범위 안이다 | 그냥 고친다 |

**같은 일을 {{issueTool}} 와 {{cardTool}} 양쪽에 올리지 않는다.** 버그는 이슈에만, 작업은 Card 에만 있다.

**등록과 착수는 다르다.** 이슈·Card 는 "할 일" 을 등록하는 것이고, 작업은 사용자가
"이 카드 착수하자" 고 할 때 **그 카드를 근거로** 시작한다. 등록하면서 구현 계획까지 미리 세우지 않는다.
이슈·Card 는 **한 주제에 하나** — 잘게 쪼개지도, 여러 주제를 하나로 묶지도 않는다.

이미 등록된 사안이라도 **결정이 막혀 있으면** `detected_issues.md` 에 한 줄 올린다.
사용자가 "나중에 물어보자"고 한 것도 여기에 적는다. 양식은 그 파일을 만질 때 로드된다.
`docs/detected_issues.md` 는 여쭐 것을 모으는 로컬 문서고, 이슈는 팀에 공유하는 작업 항목이다.

## 5. 저장소 주의

- **`docs/` 는 git 미추적이다.** PRD·Card·리포트·이슈 원고는
  **로컬 전용이며 이것이 의도된 설정이다.** 아래 표의 파일 외에 예외를 늘리지 않는다.

  | 추적되는 파일 | 왜 |
  |---|---|
  {{trackedDocs}}

  `.gitignore` 는 `docs/` 가 아니라 `docs/*` 로 **내용물**을 제외한다 — git 은 제외된
  디렉터리 안의 파일을 `!` 로 되살리지 못한다. 예외는 `!docs/{경로}` 로 한 줄씩 더한다.

  **추적되는 문서는 사내 정보 검사 대상이다.** 예시 주소가 필요하면 RFC 5737 문서용 대역(`203.0.113.0/24`)을 쓴다.
- git 추적 파일에 **사내 IP·계정·경로·직함을 쓰지 않는다.** 실값은 `docs/` 안에만 둔다.
- 테스트·실행 명령은 `CLAUDE.md` 의 실행·검증 절.

## 6. 워크트리를 닫기 전에 — 미추적 기록을 메인으로 옮긴다

`docs/` 는 미추적이라 병합에 따라가지 않고, 워크트리를 지우면 함께 사라진다.

- **`git worktree remove`(또는 폴더 삭제) 전에** 그 워크트리에서 새로 만들거나 고친 미추적 문서
  (`docs/prd/`·`docs/card/`·`docs/issues/`·`docs/reports/`·`docs/detected_issues.md` 등)를 메인 디렉터리의 같은 자리로 옮긴다.
  `git status --ignored docs/` 로 남은 것을 확인한다.
- **메인의 파일을 덮어쓰지 않는다.** 메인에도 같은 파일이 있고 내용이 다르면 차이를 보여 주고 어느 쪽을 남길지 묻는다.
- **워크트리는 만들 때 잠근다** — `git worktree add --lock --reason "닫기 전에 docs/ 미추적 기록을 메인으로 복사 (core.md §6)" ...`.
  잠긴 워크트리는 `git worktree remove` 를 쳐도 git 이 거부한다. 닫는 순서는 **복사 → `git worktree unlock` → `git worktree remove`**.
- 복사한 파일 수가 원본과 같은지 확인한 뒤에 지운다. 복사 없이 지우라는 지시면 사라지는 것을 먼저 알린다.
- 워크트리에서 `.claude/` 규칙을 고쳤으면 메인 `.claude/` 에도 같은 수정을 넣는다.
