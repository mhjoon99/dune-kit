# Card · Task list 작성법 — `docs/card/`

전체 흐름은 `process.md`. Card 는 {{cardTool}} 카드의 원고다. `/card` 커맨드로 만든다.
**PRD 의 기능 하나가 카드 하나고, 카드 하나가 파일 하나다.**

## 1. 폴더와 파일명

```
docs/card/
  00-회원-관리_v0/                   ← {PRD 번호}-{PRD 제목}_v{버전 앞자리}
    01_로그인/                       ← {구분 번호}_{구분}
      01_소셜-로그인.md              ← {순서}_{기능명}.md
      02_자동-로그인.md
    02_결제/
      03_정기-결제.md
    03_알림/                         ← 나중에 생긴 구분 — 맨 아래에 붙는다
      04_가입-환영-메일.md
  PRDx/                             ← PRD 없는 카드. 구분 폴더 없음
    01_첨부-입력-비용-절감.md          ← {순서}_{제목}.md
```

- **폴더는 PRD 버전의 앞자리 단위다.** v0.2 와 v0.3 의 카드는 같은 `_v0/` 에 이어 붙인다. 앞자리가 바뀔 때만 새 폴더를 판다.
  어느 버전 파일의 카드인지는 카드 개요의 `PRD 버전` 이 가진다(§2)
- **그 안에 PRD "필요한 기능" 표의 구분마다 폴더를 하나 둔다.** 그 PRD 번호의 **모든 버전 파일**의 표를 합쳐서 본다(`prd.md` §1). 폴더명은 `{구분 번호}_{구분}`(띄어쓰기는 `-`).
  표에서 구분 칸이 비어 있으면 바로 위 행의 구분이다(`prd.md` §3)
- **구분 번호는 PRD 폴더 안에서 01 부터**, 표에 처음 나온 순서대로 준다. **재사용하지 않고 바꾸지도 않는다** —
  같은 파일에 더해졌든 새 버전 파일에서 왔든, 구분이 새로 생기면 그 PRD 의 가장 큰 구분 번호(trash 의 같은 PRD 폴더와 그 PRD 모든 버전 폴더의 Tech Spec 파일까지 본다) 다음을 주어 맨 아래에 붙인다.
  **그 구분의 Tech Spec 이 먼저 있으면**(그 PRD 의 어느 버전 폴더든 `tech-spec/{구분 번호}_{구분}.md`) 그 번호를 쓴다(`tech-spec.md` §2).
  새 버전 파일이 이미 있는 구분 이름을 쓰면 그 구분 폴더에 넣는다. 이미 있는 구분 폴더의 번호는 그대로 두고, 이미 있는 카드는 옮기지 않는다
- **순서번호는 PRD 폴더 전체에서 01 부터 이어 센다** — 구분이 바뀌어도 다시 01 로 돌아가지 않는다. PRD "필요한 기능" 표의 순서를 따르고, 버전 파일이 여럿이면 낮은 버전부터 센다.
  **재사용하지 않는다** — 번호를 줄 때 그 PRD 폴더의 모든 구분 폴더와 `docs/trash/complete/card/` 의 같은 PRD 폴더까지 세어 다음 번호를 준다
- **`PRDx/`** 는 PRD 를 쓰기엔 단위가 너무 작아 카드로만 등록해 작업하는 일의 자리다. 구분 폴더를 두지 않는다
- **제목은 짧게, 이 일을 모르는 사람이 봐도 무슨 일인지 알게 짓는다**. "정산 기능"·"결제 기능" 정도의 길이다.
  구현 수단(store·배치·캐시 위치)이나 내부 용어·숫자가 아니라 **무엇을 위한 일인지**를 쓴다. 자세한 것은 목적 칸에 둔다

  | 이렇게 짓지 않는다 | 이렇게 짓는다 |
  |---|---|
  | 첨부 보관 store 분리 | 브라우저 첨부 저장 개선 |
  | 첨부 앞쪽 고정 배치 | 첨부 입력 비용 절감 |
  | 예산 근접 시 출력 상한 4096 | 예산 부족 시 답변 길이 제한 |

## 2. 템플릿

```markdown
# {기능명}

### 개요

- 목적: (이 작업을 왜 하는가. 배경)
- PRD 버전: v{버전} (이 기능이 적힌 PRD 파일의 버전. `PRDx` 카드는 이 줄을 뺀다)
- 링크: (PRD 또는 Tech Spec 의 {{docsTool}} URL — 사용자가 채운다)

### 할 일 (To-Do)

- [ ] (작업자가 할 일 1 — "…하도록 수정")
- [ ] (작업자가 할 일 2 — "… 추가")

### 완료 조건 (Done)

- (이 조건이 충족되면 작업 끝)
```

- **할 일 칸이 곧 Task list 다.** 따로 Task list 절을 만들지 않는다. {{cardTool}} 에는 이 체크박스들을 카드의 Task list 로 넣는다
- **`PRD 버전` 은 그 기능이 적힌 PRD 파일의 버전을 끝자리까지 적는다**(`v0.4`). 주간보고가 버전마다 진행률을 낼 때 이 줄로 카드를 가른다(`weekly-report.md` §3). 빼먹지 않는다
- **`링크` 는 비워 둔다.** {{docsTool}} URL 이라 내가 채울 수 없다. `PRDx` 카드도 비워 둔다
- **할 일은 작업자 입장에서 쓴다**. 카드는 작업자가 집어 드는 일감이다 —
  "무엇이 된다" 는 결과 서술이 아니라 **"무엇을 하도록 수정·추가·구현·확인"** 으로 끝낸다

  | 이렇게 쓰지 않는다 (사용자 입장) | 이렇게 쓴다 (작업자 입장) |
  |---|---|
  | 모델이 지원하는 크기만 고를 수 있다 | 선택한 모델이 지원하는 크기 및 비율만 고를 수 있도록 수정 |
  | 종료된 이미지 모델이 모델 선택 목록에 보이지 않는다 | 종료된 이미지 모델을 모델 선택 목록에서 제거 |
  | 브라우저 저장 용량이 모자라면 안내가 보인다 | 브라우저 저장 용량이 모자랄 때 안내가 보이는지 확인 |

  "무엇이 된다" 는 서술은 **완료 조건** 칸에 쓴다

## 3. PRD 에서 옮기는 법

| PRD "필요한 기능" 표 | Card |
|---|---|
| 구분 | 구분 폴더 `{구분 번호}_{구분}`(§1) |
| 기능 | 제목(`# …`)과 파일명 |
| 사용자가 할 수 있어야 하는 일 | **할 일** — `•` 하나가 `- [ ]` 하나. **작업자 입장 문장으로 바꿔 옮긴다**(§2). 항목 수와 뜻은 그대로 둔다 |
| 완료 기준 | **완료 조건** — 그대로 옮긴다 |

- PRD 의 기능·할 일이 고쳐지면(`(추가_YYYY-MM-DD)`) **카드도 같은 작업에서** 고친다. 표시도 같이 옮긴다
- 작업자 입장이라고 해서 파일·계층 단위로 쪼갠 구현 작업(API 추가·화면 수정·마이그레이션)을 적지 않는다.
  할 일은 **"사용자에게 무엇이 되도록 고치는가"** 한 줄이고, 그것을 어떻게 나눠 만드는지는 착수할 때 정한다
- **간결하게 쓴다.** 설계·계약값은 Tech Spec 에 두고, 구현 순서는 착수할 때 정한다

## 4. 카드를 만들어도 착수하지 않는다

카드는 할 일을 등록한 것이다. 구현은 **사용자가 그 카드 착수를 지시했을 때만** 시작한다(`process.md` §4).

## 5. 완료 표시

체크박스를 `[x]` 로 바꾸고 **옆에 완료 시각을 적는다**(표기는 `docs-format.md`).

```markdown
- [x] 크롤링한 데이터를 불러오도록 구현 완료:2026-08-14 오후 5:24
```

- 할 일 문장은 그대로 두고 **끝에 한 칸 띄워 `완료:{시각}`** 을 붙인다. `완료:` 를 빼거나 문장 끝 동사에 붙이지 않는다(`…로 수정:2026-…` ✗)

- **테스트 통과를 확인한 뒤에만** `[x]` 로 바꾼다. 검증 없는 완료 표시를 금지한다
- **취소선을 쓰지 않는다. 항목을 지우지 않는다.** 일부만 끝났으면 끝난 항목만 `[x]` 로
- 완료 시각은 주간보고가 "그 주에 손댄 카드" 를 가리는 근거다(`weekly-report.md`). 빼먹지 않는다

## 6. 완료된 카드는 옮긴다

**할 일 전 항목이 `[x]` 이고 완료 조건까지 확인되면** 그 카드는 완료다.
지우는 것이 아니라 **폴더 구조째 옮긴다.** 일부만 끝났으면 옮기지 않는다.

**`docs/card/` 아래의 경로를 한 글자도 바꾸지 않고 `docs/trash/complete/card/` 아래에 그대로 둔다** —
PRD 폴더명, 구분 폴더의 번호와 이름, 파일명 모두 같다. `PRDx/` 카드도 `docs/trash/complete/card/PRDx/` 로 간다.

```
docs/card/00-회원-관리_v0/01_로그인/01_소셜-로그인.md
  → docs/trash/complete/card/00-회원-관리_v0/01_로그인/01_소셜-로그인.md
docs/card/PRDx/01_첨부-입력-비용-절감.md
  → docs/trash/complete/card/PRDx/01_첨부-입력-비용-절감.md
```

- trash 쪽에 같은 PRD 폴더·구분 폴더가 이미 있으면 **그 안에 넣는다.** 이름이 비슷한 폴더를 새로 만들지 않는다
- 옮긴 뒤 비게 된 구분 폴더는 `docs/card/` 쪽에서 지운다. PRD 폴더는 그대로 둔다
