# 작업 태도 (항상 적용)

## 1. 결정 ≠ 착수 지시

사용자가 선택지 중 하나를 고른 것("A로 가자")은 **방향 결정**이지 지금 구현을 시작하라는 지시가 아니다.

- 결정을 받으면 문서·기록 반영까지만 하고 **"지금 할지 / 새 세션에서 할지, 어디(브랜치·워크트리)서 할지"** 를 묻는다
- 새 구현 착수, 워크트리·브랜치 생성, 워크트리 정리(삭제)는 **각각 따로** 확인받는다
- 애매하면 짐작해서 만들지 말고 묻는다. 묻는 것은 착수이고, 등록(`core.md` §4)은 묻지 않는다

## 2. 사내 매뉴얼은 원문 그대로 룰로 옮긴다

사용자가 준 사내 매뉴얼을 `.claude/rules/*.md` 로 옮길 때 **요약하지 않는다.**

- 템플릿은 원문 그대로 두고, 「참고 사항」의 목적·필수 항목·이유까지 **전부** 옮긴다
- 저장소 고유 규칙은 원문 절 **뒤에** 따로 덧붙인다 — 원문과 섞지 않는다
- 그 룰로 문서를 쓸 때도 필수 항목을 전부 채운다. 해당이 없으면 절을 지우지 않고 `해당 없음 — {이유}`
- 사용자가 룰 파일을 직접 고쳤으면 덮어쓰지 않고 그 위에 맞춘다

## 3. 응답과 문자열

- 응답·문서는 **한국어**. 코드 식별자·명령은 원문 그대로
- 사내에 올라가는 문서 원고(PRD·Tech Spec·보고)는 **문서체**로 쓴다. "우리는 ~한다"·"~의 몫이다" 같은 구어를 쓰지 않는다
- Always write Korean (and other non-ASCII) strings in tool-call parameters as literal UTF-8; never as \uXXXX unicode escape style.

## 4. 메모리

- 자동 메모리는 **이 저장소의 `.claude/memory/`** 에 쌓인다(`.claude/settings.local.json` 의 `autoMemoryDirectory`).
  사용자가 직접 열어 보고 고치는 자리다 — 사용자가 고친 내용은 되돌리지 않는다
- 사용자 지시는 메모리에만 두지 말고 **해당 룰에도 넣는다.** 메모리는 "왜" 를, 룰은 "어떻게" 를 가진다
