# {{issueTool}} 이슈 원고 — `docs/issues/`

언제 이슈로 올리는지는 `core.md` §4. 여기는 원고 형식과 **type** 고르는 법이다.

## 1. 위치·단위

- 원고는 **전부 `docs/issues/`** 에 둔다. 파일명은 `{순번}_{주제}.md`
- **한 주제에 이슈 하나.** 카드 단위로 쪼개지도, 여러 주제를 하나로 묶지도 않는다
- **이슈로 올리는 것은 장애와 버그다.** 해야 할 작업(기능 추가·개선·리팩터링·정리)은 이슈가 아니라
  **Card** 로 만든다(`process.md` §3). 작업을 이슈로 올리지 않는다
- 이슈를 쓰면서 새 Card 를 만들지 않는다. 대신 그 버그가 고치는 기능의 Card 가 있으면 **그 카드에 할 일 한 줄**을 더한다(`card.md` §7). 자세한 내용은 이슈에만 둔다

## 2. type — 셋 중 하나를 반드시 고른다

| type | 정의 | 언제 | 예 |
|---|---|---|---|
| **Incident** | 서비스가 **계획에 없이 멈추거나 품질이 떨어진** 상태 | 지금 사용자가 못 쓰고 있다 → **복구가 최우선**, 발견 즉시 처리 | stage·운영 접속 불가, 외부 연동 서버 다운, 알림이 전부 실패 |
| **Issue** | 고쳐야 할 **문제** — 버그·오동작 | 기록하고 추적할 문제 | 화면 깨짐, 선택한 값이 무시됨, 비용이 새는 구조 |
| **Task** | 장애·오류가 아닌, **계획해서 하는 명확한 작업** | **새로 쓰지 않는다** — 작업은 Card 다 | 문서 작성, 수동 점검·실측, 리포트, 정기 점검 |

헷갈리면 이렇게 가른다.
1. 지금 서비스가 망가져 있나? → **Incident**
2. 고칠 "문제"(버그·오동작)가 있나? → **Issue**
3. 둘 다 아니고 해야 할 일만 있다 → **이슈가 아니다. Card 로 만든다**(`card.md`)

표의 Task 행은 이미 올라간 이슈를 읽을 때를 위해 남겨 둔다. 새 원고에 Task 를 고르지 않는다.

## 3. type 과 템플릿은 다른 축이다

템플릿은 **본문 모양**, type 은 **성격**이다. 따로 고른다.

| type | 템플릿 | 라벨 |
|---|---|---|
| Incident | `Incident.md` — 영향 범위·임시 조치·원인·재발 방지 | `~incident` |
| Issue | `Bug.md` — 재현, 기대와 실제, 환경 | `~bug` |

장애를 복구한 뒤 남은 버그 수정은 **별도 Issue(`Bug.md`)** 로 연다 — Incident 의 「🛡 재발 방지」에 그 번호를 적는다.
템플릿 끝의 `/label ~bug`·`/label ~incident` 는 **라벨**이다. type 과 다르다. 지우지 않는다.

## 4. 원고 머리 형식

```
제목: <한 줄>
type: Incident | Issue — <왜 이 type 인지 한 구절>
{{issueTool}}: #<번호> | 미등록
템플릿: Bug | Incident

---

<템플릿 본문 그대로>
```

등록할 때 type 넣는 법
- 화면: 새 이슈 작성 화면의 **Type** 드롭다운
- API: `POST /projects/:id/issues` 의 `issue_type`(`issue`·`incident`)

`{{issueTool}}:` 줄은 원고를 쓸 때 `미등록`, 이슈가 올라간 뒤 번호로 바꾼다. 카드의 할 일 줄도 같은 번호로 바꾼다.

## 5. 본문 금지

- 미추적 문서(`docs/prd/`·`docs/card/`·`docs/reports/` 등)를 링크하지 않는다. 링크할 수 있는 것은 이슈·MR 번호와, git 추적 문서(`core.md` §5)뿐이다 — `git ls-files` 로 확인한다
- 사내 IP·계정·경로·직함은 쓰지 않는다

## 6. 해결되면 — `docs/trash/complete/issues/` 로 옮긴다

- 🏁 완료 기준이 **전부 `[x]`** 가 되면 원고를 `docs/trash/complete/issues/` 로 옮긴다(파일명 그대로)
- `[x]` 는 **실제로 확인한 뒤에만** 친다 — 재현 절차를 다시 돌려 통과를 본다. 확인한 날짜·시각과 커밋을 그 줄에 적고,
  🔗 참고에 고친 커밋을 `✅ 해결:` 한 줄로 남긴다
- 새 이슈의 순번은 `docs/issues/` 와 `docs/trash/complete/issues/` **양쪽**을 세어 다음 번호를 준다
