# 주간 보고 형식 — `docs/reports/weekly/`

전체 흐름은 `process.md`. 절차는 `/weekly-report` 커맨드에 있고, 여기는 형식과 판정 규칙이다.

## 1. 형식

파일 첫 줄만 제목이고, 그 아래는 보고 시스템에 붙여 넣을 본문 그대로다.

```markdown
# {YYYY-MM-DD} ~ {YYYY-MM-DD} 주간 보고

<이번주 수행 내역>

1. {프로젝트명}
■ {Card = PRD 의 기능}
○ (완료) {할 일}
○ (미완료) {할 일} [대응 방안: {…}]
■ {Card}
○ (완료) {할 일}
■ {Card}
○ (미완료) {할 일} [대응 방안: {…}]

<다음주 예정 사항>

1. {프로젝트명}
■ {Card}
○ {할 일}
```

## 2. 무엇이 무엇인가

| 보고서 | 출처 |
|---|---|
| ■ | **Card.** 제목은 PRD 의 기능명 그대로 |
| ○ | 그 카드의 **할 일 항목.** 문장은 카드 그대로 |
| (완료) / (미완료) | 체크박스 `[x]` / `[ ]` |

Card 는 **`docs/card/` 와 `docs/trash/complete/card/` 양쪽**에서, PRD 폴더 아래 **구분 폴더까지** 읽는다 — 완료된 카드는 뒤쪽에 있다.

## 3. 이번주 수행 내역

- **그 주에 손댄 카드만 적는다.** 손댔는지는 체크 옆 완료 시각이 그 주인지, 그 주 일일 리포트
  「오늘 작업한 내용」에 그 카드 작업이 있는지로 가린다
- 손댄 카드는 **할 일을 전부** 적고 항목마다 (완료)/(미완료) 를 붙인다
- **(미완료) 에는 `[대응 방안: …]` 을 붙인다.** 일일 리포트에서 찾고, **없으면 사용자에게 묻는다.** 지어내지 않는다
- 카드에 `PRD 버전` 줄이 없으면 짐작하지 말고 사용자에게 묻는다
- 한 프로젝트에 PRD 가 여럿이면 PRD 번호 순으로, 그 안에서 버전(카드 개요의 `PRD 버전`) 순으로 ■ 를 놓는다

## 4. 다음주 예정 사항

- 미완료 Card 의 남은 할 일과 **가장 최근** 일일 리포트의 「이어서 할 일」에서 실제로 다음 주에 손댈 것을 고른다
- ■ Card / ○ 할 일로 적는다. (완료)/(미완료) 를 붙이지 않는다
- 상대 쪽 답을 기다리는 일은 "… 대응" 한 줄(■)로 쓴다

## 5. PRD 밖의 일

`PRDx` 카드와 {{issueTool}} 이슈로만 처리한 버그 수정은 **기본으로 넣지 않는다.**
보고서를 쓸 때 그 주의 `PRDx` 카드와 버그 수정 목록을 사용자에게 보여 주고 **넣을지 묻는다.**
넣기로 하면 그 프로젝트의 PRD 카드 ■ 뒤에 ■ 로 덧붙인다.

## 6. 규칙

- **성격 태그를 쓰지 않는다.** `(기능 개발)`·`(문서)`·`(협의)`·`(검증)` 같은 태그를 붙이지 않는다.
  ○ 앞에 오는 것은 (완료)·(미완료) 뿐이다
- **읽는 사람은 코드를 모른다.** 파일명·함수명·컬럼명·커밋 해시·브랜치명·API 경로를 쓰지 않는다.
  ■·○ 문장을 PRD·Card 에서 그대로 가져오는 것도 이 때문이다 — 대응 방안도 같은 눈높이로 쓴다
- **프로젝트명 블록은 {{reportProjects}}.** 그 주에 작업이 없는 블록은 뺀다
- **Card 와 일일 리포트에 없는 일은 쓰지 않는다.** 비어 보여도 지어내지 않는다
- 사내 IP·계정·경로·직함을 쓰지 않는다(`core.md` §5). 사람은 이름을 쓰지 않는다
- 날짜 표기는 `docs-format.md` — 파일명 `YYMMDD`(그 주 **월요일**), 본문 `YYYY-MM-DD`
- 주간 보고는 일일 리포트를 대체하지 않는다. 빠진 날이 있으면 먼저 `/daily-report` 로 채우라고 알린다
