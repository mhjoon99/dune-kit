# /tech-spec

Tech Spec 을 작성한다. **형식은 `.claude/rules/tech-spec.md` 에 있다 — 먼저 읽는다.** 흐름은 `process.md`.
그 룰 파일이 이 저장소에 없으면 쓰지 말고, `/init` 으로 work-kit 묶음을 먼저 깔라고 알린다.

## 절차

1. `$ARGUMENTS` 로 대상 PRD **버전**과 **구분**을 정한다(기능을 주면 그 기능이 속한 구분이다 — 구분 하나에 Tech Spec 하나). 비어 있거나 어느 PRD 의 것인지 모호하면 묻는다.
2. **Tech Spec 이 필요한 일인지 본다**(`tech-spec.md` §1). Card 만으로 충분해 보이면 그렇게 말하고 쓸지 묻는다.
3. 근거를 읽는다 — 그 기능이 적힌 버전의 PRD 파일의 해당 행, 정본(합의된 명세 문서)이 있으면 그 해당 절,
   그리고 **기존 구현 실태**(전제하는 것이 이미 있는지 실제 파일을 연다).
4. 구분 번호를 정한다(`tech-spec.md` §2). 구분 번호는 Card 구분 폴더가 이미 있으면 그 번호
   (`docs/card/` 와 `docs/trash/complete/card/` 의 같은 PRD 폴더를 본다), 없으면 `card.md` §1 의 규칙으로 낸다.
   **같은 버전 폴더에** 그 구분의 Tech Spec 이 이미 있으면 새로 만들지 않고 그 파일을 고친다.
   다른 버전 폴더에만 있으면 이 버전 폴더에 새로 쓴다 — 이전 버전의 Tech Spec 은 고치지 않는다.
5. 템플릿(`tech-spec.md` §3)을 채운다.
   - 계약값은 **정본의 절 번호와 함께** 옮겨 적는다. 문서에 없는 값을 채우지 않는다
   - `## 3. 기술 상세 설계` 는 **5가지 핵심 항목(① 아키텍처 ② 스키마 ③ API ④ 예외 ⑤ 보안·성능)을 모두 둔다**
     (`tech-spec.md` §4·§5). 해당이 없으면 절을 지우지 않고 `해당 없음 — {이유}` 한 줄
   - 다 쓴 뒤 **핵심 목적 3가지**(위험 최소화·병렬 작업의 기준·지식의 자산화)로 한 번 읽는다
   - 결정이 남으면 §2 끝 `### 팀 결정 대기` 에 **선택지와 함께** 적는다. 임시 기본값을 넣지 않는다
6. `docs/prd/{NN}-{제목}_v{버전}/tech-spec/{구분 번호}_{구분}.md` 로 저장한다. 상태는 `⚪ 초안`.

## 기존 Tech Spec 을 고칠 때

- `최종 수정일` 을 오늘로 바꾼다. 번호와 파일명은 바꾸지 않는다
- 이미 `[x]` 인 항목을 지우거나 되돌리지 않는다. 내용이 바뀌어 다시 해야 하면 새 항목으로 더한다

## 끝나면

- 저장한 경로, `### 팀 결정 대기` 에 남은 것, **비워 둔 칸**(상위 PRD 의 문서 도구 URL 등)을 알린다
- **Tech Spec 은 완료돼도 `docs/trash/` 로 옮기지 않는다**
