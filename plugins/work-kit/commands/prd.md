# /prd

PRD 를 작성한다. **형식·버전 규칙은 `.claude/rules/prd.md` 에 있다 — 먼저 읽는다.** 흐름은 `process.md`.
그 룰 파일이 이 저장소에 없으면 쓰지 말고, `/init` 으로 work-kit 묶음을 먼저 깔라고 알린다.

## 절차

1. `$ARGUMENTS` 를 본다. 비어 있으면 무엇의 PRD 인지 묻는다.
2. `docs/prd/` 를 확인해 **새 PRD 인지 기존 PRD 인지** 가른다.

### 새 PRD

**PRD 초안은 사용자가 쓴다.** 초안(파일 경로나 붙여 넣은 글)을 받아 형식만 맞춘다. 초안이 없으면 먼저 달라고 한다 —
사용자가 처음부터 같이 쓰자고 할 때만 질문으로 받아 적는다.

3. PRD 번호를 정한다 — `docs/prd/` 의 버전 폴더들 중 가장 큰 `NN` 다음 번호. 재사용하지 않는다.
4. 초안을 템플릿(`prd.md` §2)의 네 절에 맞춰 옮기고 문서체로 다듬는다(`prd.md` §5).
   **내용은 더하지도 빼지도 않는다.** 초안에 없는 칸은 비워 두고 무엇이 비었는지 알린다. 지어내지 않는다.
5. "필요한 기능" 표의 **구분·기능 나눔을 사용자에게 보여 주고 확인받는다** —
   기능 하나가 Card 하나가 되므로 이 나눔이 이후 전부를 정한다. 초안의 나눔을 바꾸고 싶으면 제안만 한다.
6. 참고 사항(`prd.md` §4)의 다섯 항목으로 확인해 **빠진 것을 알린다.** "이번 범위에서 제외할 것"·"성공 지표" 절을
   더할지 사용자에게 묻는다 — 더한다면 성공 지표는 측정할 수 있는 수치 기준으로 쓴다.
7. `docs/prd/{NN}-{제목}_v{버전}/{NN}-prd_{제목}_v{버전}.md` 로 저장한다(`prd.md` §1). `tech-spec/` 폴더는 만들지 않는다. 첫 버전 번호는 사용자에게 묻는다.

### 기존 PRD — 기능을 더하거나 고칠 때

사용자가 "이 기능을 PRD 에 더해야 할 것 같다" 고 했을 때 시작한다. **어느 쪽으로 처리할지 내가 정하지 않는다.**

3. 그 PRD 번호의 **모든 버전 파일**의 「1. 목적」을 읽고, 더하려는 기능이 목적에 맞는지 본 뒤 **제안한다**(`prd.md` §1).
   목적의 어느 문장에 맞는지·어긋나는지를 근거로 붙인다. 여기서 멈추고 사용자의 결정을 기다린다.

   | 제안 | 처리(사용자가 정한 뒤) |
   |---|---|
   | 목적에 맞는다 | 그 버전 파일의 표에 더하고 **고친 항목 옆에 `(추가_YYYY-MM-DD)`**. 구분이 새로 생겨도 같다 |
   | 목적과 어긋난다 | 버전 업 — **새 버전 폴더에 새 파일**. 새 목적과 **새 기능만** 적는다. 이전 버전의 기능은 옮겨 적지 않고, 이전 버전의 폴더는 건드리지 않는다 |

4. 버전 업이면 새 버전의 「1. 목적」을 사용자에게서 받는다. 지어내지 않는다. 버전 번호는 그 PRD 의 가장 큰 버전 다음이다
   (v0.3 → v0.4). 앞자리를 올릴지는 사용자에게 묻는다.
5. 기능·할 일을 고쳤으면 **해당 Card 도 같은 작업에서** 고친다(`card.md` §3).
6. 고친 파일의 `최종 수정일` 을 오늘로 바꾼다.

## 끝나면

- 저장한 경로와, **비워 둔 칸**(PM, 사내 문서 도구에 붙인 뒤 채울 것 등)을 알린다
- Card 를 만들지는 않는다. 필요하면 `/card {PRD 파일}` 을 안내한다
- **PRD 는 완료돼도 `docs/trash/` 로 옮기지 않는다**
