# /card

Card 를 작성한다. **형식은 `.claude/rules/card.md` 에 있다 — 먼저 읽는다.** 흐름은 `process.md`.
그 룰 파일이 이 저장소에 없으면 쓰지 말고, `/init` 으로 work-kit 묶음을 먼저 깔라고 알린다.

## 절차

1. `$ARGUMENTS` 를 본다. `docs/prd/` 의 PRD(파일이나 버전 폴더)를 가리키면 **PRD 카드**, 제목이면 **PRDx 카드**다. 비어 있으면 묻는다.

### PRD 카드 — `/card {PRD 파일}`

2. 그 PRD 번호의 **모든 버전 파일**의 "필요한 기능" 표를 읽는다 — 버전 파일은 누적이 아니라 각자 자기 기능만 가진다(`prd.md` §1).
   낮은 버전부터 본다. 기능마다 **어느 버전 파일의 것인지** 기억해 둔다.
3. 폴더를 정한다 — `docs/card/{PRD 번호}-{PRD 제목}_v{버전 앞자리}/{구분 번호}_{구분}/`. 표에서 구분 칸이 비어 있으면
   **바로 위 행의 구분**이다(같은 구분이 이어질 때 비워 두는 표기다, `prd.md` §3).
   구분 번호는 `card.md` §1 — **이미 있는 구분이면 그 번호를 그대로 쓴다**(`docs/card/` 에 없으면 `docs/trash/complete/card/` 의 같은 PRD 폴더에서 찾는다).
   그 구분의 Tech Spec 이 그 PRD 의 버전 폴더(`docs/prd/{NN}-{제목}_v{버전}/tech-spec/`)에 먼저 있으면 그 파일의 구분 번호를 쓴다.
   어디에도 없는 구분이면 `card.md` §1 의 규칙으로 번호를 준다.
4. 표의 기능마다 카드가 있는지 본다. PRD 폴더 아래 **모든 구분 폴더**와 **`docs/trash/complete/card/` 의 같은 PRD 폴더**까지 본다 — 완료된 카드는 거기 있다.

   | 상태 | 처리 |
   |---|---|
   | 카드 없음 | 새로 만든다. 개요의 `PRD 버전` 에 그 기능이 적힌 파일의 버전을 적는다. 순서번호는 그 PRD 의 카드 전부(양쪽, 모든 구분)를 합쳐 가장 큰 번호 다음 |
   | 카드 있음, PRD 와 같음 | 건너뛴다 |
   | 카드 있음, PRD 가 고쳐짐(`(추가_YYYY-MM-DD)`) | 카드의 할 일·완료 조건을 맞춘다. 이미 `[x]` 인 항목은 건드리지 않는다 |

5. 파일명은 `{순서}_{기능명}.md`(구분은 폴더가 가진다).
6. 옮기는 법은 `card.md` §3 — 기능 → 제목, "사용자가 할 수 있어야 하는 일" 의 `•` 하나 → `- [ ]` 하나,
   "완료 기준" → 완료 조건. **할 일은 작업자 입장 문장으로 바꿔 옮긴다**("…하도록 수정·추가·구현·확인", `card.md` §2).
   완료 조건은 문장을 바꾸지 않는다.
7. **목적**은 표에 없는 칸이다. **그 기능이 적힌 버전 파일**의 「1. 목적」과 같은 버전 폴더에 있는 그 구분의 Tech Spec 에서 이 기능의 배경을 한두 문장으로 옮긴다.
   근거가 없으면 지어내지 말고 비워 둔 뒤 알린다.

### PRDx 카드 — `/card {제목}`

2. PRD 를 쓰기엔 작은 일인지 본다. PRD 기능에 속하는 일이면 그 PRD 를 고치는 쪽(`/prd`)을 먼저 권한다.
3. 목적·할 일·완료 조건을 사용자에게서 받거나, 대화에서 이미 정해진 것으로 채운다. 지어내지 않는다.
   **할 일은 작업자 입장으로 쓴다**(`card.md` §2) — "…된다" 가 아니라 "…하도록 수정".
4. 순서번호는 `docs/card/PRDx/` 와 `docs/trash/complete/card/PRDx/` **양쪽을 합쳐** 가장 큰 번호 다음이다. 재사용하지 않는다.
5. `docs/card/PRDx/{순서}_{제목}.md` 로 저장한다. **제목은 짧게, 남이 봐도 알아듣게**(`card.md` §1) — 구현 수단·내부 용어를 넣지 않는다.
6. 완료 조건에 **아직 정해지지 않은 결정**이 끼면 카드에 묻어 두지 않는다 — `docs/detected_issues.md` 에 선택지로 올리고(`core.md` §4), 완료 조건에는 그 결정을 따른다고만 적는다.

## 끝나면

- 만든 카드·고친 카드·건너뛴 카드를 표로 알린다
- **`링크` 칸은 비워 둔다** — 사내 문서 도구의 URL 은 사용자가 채운다
- 구현을 시작하지 않는다. 착수는 사용자가 지시한다(`process.md` §4)
